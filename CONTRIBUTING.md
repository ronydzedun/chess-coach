# Contributing

Thanks for considering a contribution. Keep changes focused, describe the user-visible effect, and include or update relevant tests when behavior changes.

## Before opening a pull request

1. Read the workspace structure and development commands in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
2. Run the formatting, build, test, and Clippy checks listed there.
3. In the pull request, explain the problem, the change, and the checks you ran. Include screenshots only when they help explain a UI change.

Please do not bundle unrelated formatting or dependency updates with a feature or fix. Preserve the project's existing license headers and avoid adding generated build output.
